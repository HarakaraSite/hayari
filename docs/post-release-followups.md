# Hayari post-release 修正メモ

記録日: 2026-07-24

常用環境・iPhone ReadKit 同期で `v1.0.3` の基本動作を確認した後に見つかった、UI/検索改善候補と実施結果を記録する。

## 1. サイドバーの未読数を固定位置へ揃える

### 状態

- 実装・DOM 検証済み。固定幅・等幅数字・`999+` 表示を追加し、favicon が取得できない子フィードも含めてフォルダ・フィードのバッジ右端が揃うことを Playwright で確認した。Unread では未読0件、Starred ではスター付き記事0件のフィードと該当する子がないフォルダを隠し、All では再表示されることも確認した。

### 観察

フィード名の長さ、フォルダ展開、インデントにより未読数バッジの横位置が行ごとに異なる。右端が一定でないため、一覧全体が凸凹に見える。

### 受け入れ条件

- フォルダ、通常フィード、ネストしたフィードを混在させても、未読数の右端が同じ x 座標に揃う。
- フィード名は残りの可用幅で省略され、未読数を押し出さない。
- 数字は `font-variant-numeric: tabular-nums` で等幅化し、固定幅の右寄せ列に表示する。
- 表示は最大 3 桁とし、1,000 件以上は `999+` と表示する。
- Unread 表示では未読 0 件のフィードを隠し、未読の子フィードがないフォルダも隠す。既読・未読の更新直後に表示を同期する。
- Starred 表示ではスター付き記事が 0 件のフィードを隠し、該当する子フィードがないフォルダも隠す。スターの切替直後に表示を同期する。
- サイドバーの件数バッジは Unread では未読数、Starred ではスター数を表示し、All では表示しない。
- 既存のフォルダ展開、選択状態、未読数の更新を後退させない。

## 2. Hayari の favicon を追加する

### 観察

ブラウザタブ、ブックマーク、ホーム画面に表示される Hayari 自体のアイコンがない。

### 調査・実装条件

- Hayari を識別できる小さなアプリアイコンを用意する。角丸の印章風アウトラインに「流」を入れる。
- SVG を埋め込みアセットとして配信し、`index.html` とログイン画面の `<head>` から参照する。ログイン後のサイドバー見出しでも、Hayari の左に同じマークを表示する。
- ライト／ダークテーマと小さい表示サイズで判別できることを確認する。

## 3. 検索のヒット漏れを再現・修正する

### 観察

検索ボックスから記事を検索したとき、該当しそうな記事がヒットしないことがある。

### 調査・実装条件

- 再現済み: あにまんch、`All`、タイトルに `【ハンターハンター】` を含む記事が表示中に `ハンター` を検索すると 0 件になる。
- 検索対象は記事タイトルのみとする。本文は検索索引へ保存しない。
- SQLite FTS5 の標準トークン化では、`ハンターハンター` のような連続した日本語トークンに対する部分一致 `ハンター` は一致しない。タイトル専用の trigram 索引を使い、3文字以上の任意部分一致を扱う。1〜2文字の検索はタイトルだけを対象にフォールバックする。
- 検索語、対象記事のタイトル・本文・フィード名、選択中の表示範囲（Unread/Starred/All）、時刻を記録して再現ケースを作る。
- FTS の索引対象、同期タイミング、検索 API の条件、UI 側の検索要求と表示更新を順に確認する。
- 再現したケースを自動テストに固定し、想定する検索範囲と大小文字・日本語トークン化の挙動を明文化する。

## 4. 記事本文の外部リンクを新しいタブで開く

### 観察

記事本文内のリンクが同じタブで開き、Hayari の一覧・記事位置から離れてしまう。

### 受け入れ条件

- 記事本文内の外部リンクは新しいタブで開く。
- `target="_blank"` と `rel="noopener noreferrer"` を付与し、元タブを保護する。
- 内部 UI 操作や記事本文以外のリンクの挙動を意図せず変えない。

## 5. フィード単位のタイトル非表示フィルタ

### 合意した仕様

- Hayari の Web UI で、フィードごとにキーワードを設定する。
- 記事タイトルにキーワードがリテラル部分一致した新規記事は、サーバー側の取り込み時に完全非表示にする。
- Google Reader／FreshRSS 互換 API の対象にはせず、Hayari 独自 API と Web UI だけで管理する。

### 状態

- 実装・テスト済み。フィード編集ダイアログで `ハンター,サッカー` のように入力でき、空要素・周囲の空白・重複を除いて保存する。
- 各キーワードは OR 条件のリテラル部分一致（大文字・小文字を区別しない）であり、一つでもタイトルに含まれる記事はサーバー側で非表示にする。保存時に既存記事も再評価し、キーワードを外した記事は再表示する。

### 現状との差分

- 既存の `/api/filters` は独自 API の正規表現ルールであり、`hide` は新しいフィード設定と同様に完全非表示とする。この機能のカンマ区切りキーワード欄は、より単純なフィード単位設定として併存する。
- 記事を削除せず非表示状態として保持するため、後からキーワードを外して再表示できる。
